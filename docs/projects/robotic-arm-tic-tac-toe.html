ELEC3300 Project - Robotic Arm Tic Tac Toe

Sept - Nov 2023

HKUST Course Project: ELEC3300 Introduction to Embedded Systems

🎯 Overview

Robotic Arm Tic Tac Toe Full Setup

This project is a two-player competitive game where each player controls a 5-DOF robotic arm with a clamp. The goal is to pick up ping-pong balls from a personal storage zone and place them into three transparent cups in the centre, forming a line (like Tic-Tac-Toe). Unlike traditional Tic-Tac-Toe, both players start at the same time, so victory depends on speed and precision rather than turn order.

2 Robotic Arms

5 servo motors each, controlled via PWM

STM32 F103 Mainboards

Two boards, one per player, communicating via UART

Custom Controllers

4 analog joysticks, touchscreen LCD, GPIO buttons

Image Processing

Camera detects ball colours in cups for automated scoring

🎮 Robotic Arm Control Modes

The system offers four progressively autonomous control modes:

Mode Description Inputs Used
Full Manual Each servo angle controlled independently via multiple joysticks. Joysticks A-D (one per joint)
Semi Manual Joysticks control clamp position (x, y, z, θ); inverse kinematics runs on-board. Joysticks for Cartesian axes + yaw
Semi Auto Player selects target via touchscreen; arm automatically moves with safe trajectory. Touchscreen for target, clamp toggle button
Full Auto AI controls the entire sequence: pick balls, decide cup, place, repeat. Camera feedback + pre-programmed logic

Semi-Auto “Angle-Percentage” Movement

When moving between predefined positions, the arm uses a percentage-based synchronisation: the servo with the largest angular change determines the movement duration; all other servos move proportionally so they all finish at the same time.

Original: a=60°, b=120°, c=120°, yaw=90°
Target: a=90°, b=200°, c=270°, yaw=90°
Max difference: c (150°)
Percent = (current_c - 120°) / (270° - 120°)
a = 60° + Percent × (90°-60°)
b = 120° + Percent × (200°-120°)
yaw = 90°

Semi-Auto 3-Segment Movement (Avoid Sweeping)

To prevent the arm from knocking over other balls, each target position has a “safe” intermediate point. The arm moves in three segments: current safe → next safe → target.

Red path: dangerous straight line; green/blue: safe intermediate positions.

Full-Auto Sequence

In Full-Auto mode, the AI follows this loop for all 8 balls:

  1. Move to next ball position
  2. Clamp the ball
  3. Decide which cup to place into (based on game state and minimax)
  4. Move to the chosen cup
  5. Open clamp to drop the ball

📷 Image Processing & Game Logic

The system uses two cameras (one per mainboard) to monitor the three cups. Processing steps:

  1. Parameter tuning & physical filtering - adjust brightness/contrast; add white backgrounds to reduce noise.
  2. Detection - colour-based segmentation identifies which player’s balls are inside each cup.
  3. Update - results combined with confidence timer to determine game state (e.g., three-in-a-line) and drive full-auto decisions.
Filter → Detection → Update pipeline.

🔗 UART Communication & Synchronisation

  • Game start handshake - both boards exchange ready signals to begin the countdown simultaneously.
  • Data format - start byte + 3/6 bytes of ball data + checksum byte; received via interrupt and verified.
  • State sharing - one board processes cup 1 & 2, the other processes cup 3; results are exchanged so each board knows the full game state.

🧠 Challenges & Limitations

  • Computational power: STM32F103 is limited; we optimised image processing to keep it lightweight.
  • Accuracy: Servo position can deviate due to mechanical tolerances; calibration routines were implemented.
  • Clamping reliability: The clamp occasionally fails to grip a ball; we added a short delay and retry logic.
  • Lighting sensitivity: Image detection required consistent illumination; we added physical white backgrounds to reduce noise.
  • Inconsistent positions: Actual arm position sometimes differs from theoretical values due to backlash and slippage.
  • PWM precision: CCR and ARR values affect the arm’s positioning accuracy.

🕹️ Controller Design

Each player has a custom controller with 4 analog joysticks (one-directional to avoid axis interference), 3 buttons (2 on-board, 1 external), and a touchscreen LCD. All signals are wired directly to the STM32 mainboard.
